# AERMODKit 0.1 progress 02 — full v26135 registry and semantic mapping

- Date: 2026-07-29
- EPA baseline: AERMOD v26135
- Package version: 0.1.0a2

## Objective

Complete the machine-readable keyword surface before developing GIS conversion,
execution orchestration, or user interfaces. Preserve the syntax tree as the authority
while exposing a convenient read-only semantic view.

## Implemented

1. Complete statement-keyword registries for CO, SO, RE, ME, EV, and OU.
2. Explicit separation of pathway STARTING/FINISHED syntax markers from keywords.
3. Official evidence references for each pathway and the User Guide appendix.
4. GRIDCART and GRIDPOLR continuation-family contracts with STA/member/END validation.
5. Keyword dependencies, option dependencies, first/last ordering, and keyword conflicts.
6. Cross-pathway checks for SCIM, HBP, ARCFTOPT, PSDCREDIT, RANKFILE, and receptors.
7. A read-only `AermodProjectModel` semantic projection that retains the original AST.
8. A multi-pathway v26135 fixture and tests covering registry completeness, lossless
   round trips, semantic mapping, continuation balance, and dependencies.

## Design decisions

- Argument ranges are conservative for keywords with multiple documented forms. More
  precise discriminated forms will be added after official executable regression cases.
- `STARTING` and `FINISHED` are parser-level records, not ordinary statements.
- Include files are retained as references; recursive expansion and sandbox policy remain
  deferred so the lossless source document is never silently replaced.
- The semantic model is a projection, not a second editable source of truth.
